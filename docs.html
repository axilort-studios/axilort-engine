Documentation

Guides for the Axilort Engine features that are currently available.

Documentation status: These guides describe the current editor pages and browser storage behavior. Team collaboration is not documented as an available feature because the Team page currently marks it as coming soon.

This documentation page contains readable guides for the current Axilort Engine interface. Select any guide to expand it.

The guides intentionally describe only the current pages and storage behavior represented by the engine interface.

The Home page is the main starting screen. It provides navigation to Projects, Assets, Settings, Team, and Docs.

Its Quick Actions link to project creation/opening and asset importing.

The Projects page is the project-management interface. It lets the user start the new-project flow and view projects represented by the project manager.

The current project manager uses its own IndexedDB database named AxilortEngineProjects with a projects object store.

Choose ＋ New Project on the Projects page, enter a project name, and select the required parent folder when the browser supports the folder-selection flow.

The project interface is designed around creating the project folder inside the selected parent location. A project location is required by the current UI.

The Projects page contains the interface for existing projects. The project list and its actions are intended to work with project information maintained by the current project manager.

Project storage and browser filesystem access are separate concepts; a webpage cannot silently access arbitrary device folders without browser permission.

Project rows use a three-dot action control. The current Projects interface provides actions around opening and deleting projects.

Deletion is destructive. Confirm the project you want to remove before using a delete action.

The Assets page reads the real axilort-engine-data IndexedDB database. It does not create the database just to populate the Assets screen.

Available object stores are represented in the storage view. The page also uses the real storage marker as a fallback where database enumeration is unavailable.

The Assets page provides an ＋ Upload control and a multiple-file picker. Uploaded files are stored as records in the files object store when that store is available.

Each file record can contain a path, name, size, and Blob data used by the asset viewer.

Real entries in the files store can be renamed or deleted from the three-dot menu on the Assets page.

The special engine stores such as setting.json and user-data.json are storage structures, not ordinary filesystem files, so the Assets interface does not treat them as normal uploaded files.

The Assets page has an Extract control for the stored file data. It works with real file records rather than displaying a fabricated asset list.

Only data that is actually available through the browser storage API can be extracted by the page.

The engine uses a browser IndexedDB database named axilort-engine-data for its engine storage.

The current storage layout includes the object stores setting.json, user-data.json, and project. The Assets page can also work with a files store when real file records exist.

The Settings page uses the real setting.json object store in axilort-engine-data. Its settings record uses the key settings.

The current settings record stores the engine name, interface preference, system status, and an update timestamp.

{ engine, interface, systemStatus, updatedAt }

The engine storage layout includes a user-data.json object store. Its current engine initialization uses a user record for user data.

This page does not claim additional user-profile or account features that are not currently implemented in the editor UI.

The engine storage database includes a project object store. The Assets page represents it as the project/ storage area when that real store exists.

This is IndexedDB storage, not a physical folder automatically created on the device.

IndexedDB is a browser API for storing structured data locally. Databases contain object stores and records rather than ordinary desktop folders.

For Axilort Engine, this makes it possible for the web editor to keep structured engine data locally in the browser.

Browser storage is controlled by the browser and website origin. It is not the same as unrestricted access to the device's filesystem.

A web application cannot silently create arbitrary physical folders such as C:\ folders or Android/iOS filesystem directories. User permission is required for browser APIs that expose selected filesystem locations.

IndexedDB data is local to the browser profile and can be available without a network connection after the application and its resources have been loaded.

Offline availability does not mean that the same browser database automatically synchronizes across phones, computers, or operating systems.

Browser IndexedDB is scoped to the browser environment and origin. Data saved on one device is not automatically the same database on another device.

Cross-device synchronization would require an additional network-backed service or another explicit data-transfer mechanism; that is not presented as a current Axilort Engine feature here.

The current editor pages use a landscape-oriented layout. On portrait screens, the application container is rotated so the editor UI remains landscape-shaped.

This behavior is implemented in the page layout and does not change the device's operating-system orientation setting.

The Settings page displays the current engine settings and provides Save Settings. Saving writes the settings record to the real setting.json object store.

If the engine storage has not been created, the Settings page does not create it simply by being opened; the user is instructed to open the engine first.

The Team page currently states that team collaboration features are Coming Soon.

Future collaboration ideas are not described here as working features. The current page only communicates that team tools are being prepared for a future update.

The sidebar provides direct links to home.html, projects.html, assets.html, settings.html, team.html, and docs.html.

The Docs item is highlighted while this page is open. The top-right gear button opens settings.html.

The current Assets implementation is designed to show real IndexedDB stores and real file records. It does not populate the list with fictional projects or assets merely for visual appearance.

Special engine storage entries are identified separately from normal uploaded files.

Web browsers protect local files and device resources. Selecting a device folder through a browser feature requires an explicit user action and permission where supported.

Support for filesystem APIs also differs between browsers and operating systems, so a web editor should not assume unrestricted native filesystem access everywhere.
